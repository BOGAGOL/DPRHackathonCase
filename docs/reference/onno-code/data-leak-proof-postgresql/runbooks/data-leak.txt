RUNBOOK KEBOCORAN DATA ATAU CIPHERTEXT

CONTAINMENT
1. Aktifkan pimpinan insiden dan catat seluruh tindakan.
2. Cabut akses yang disalahgunakan; batasi egress.
3. Isolasi host bila perlu tanpa merusak bukti.
4. Amankan log PostgreSQL, aplikasi, OpenBao, host, jaringan, dan backup.

SCOPING
- Artefak: plaintext/ciphertext/blind index/token/backup/WAL/log.
- Tabel, kolom, tenant, jumlah record, periode, dan identitas.
- Data dibaca, diubah, atau dihapus.
- Apakah aplikasi, token decrypt, atau kunci ikut bocor.
- Metadata dan pola yang masih dapat disimpulkan.

RECOVERY
1. Tutup akar masalah dan rotasi kredensial.
2. Validasi integritas dan pulihkan layanan bertahap.
3. Penuhi kewajiban hukum/kontraktual dan komunikasi.
4. Perbarui threat model, kontrol, dan lessons learned.

Jangan menyatakan aman hanya karena artefak berupa ciphertext.
