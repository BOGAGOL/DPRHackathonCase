RUNBOOK KEBOCORAN KUNCI ATAU OTORITAS DECRYPT

LANGKAH SEGERA
1. Cabut token, sertifikat, atau workload identity.
2. Isolasi aplikasi/host dan pertahankan bukti.
3. Buat versi kunci baru; arahkan enkripsi baru ke versi tersebut.
4. Telusuri audit decrypt: identitas, waktu, sumber, volume, key version.
5. Petakan seluruh ciphertext dan backup yang terkait.
6. Jalankan rewrap/enkripsi ulang dalam batch; validasi hasil.
7. Bangun ulang kepercayaan host, pipeline, dan autentikasi workload.
8. Batasi versi lama setelah kebutuhan restore dan retensi diselesaikan.

Anggap data berpotensi terbuka jika penyerang mungkin sempat melakukan decrypt.
Jangan menghapus kunci lama secara tergesa-gesa karena dapat menyebabkan
kehilangan data permanen.
