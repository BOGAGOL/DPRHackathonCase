Database menyimpan ciphertext untuk identitas dan keuangan. Kunci disimpan terpisah di OpenBao. Pengguna sah menerima field yang sesuai perannya; analis menerima agregat berukuran minimal 5.

TERBUKTI DALAM SCOPE UJI

Perlindungan dan pemulihan

  • 734 record dan seluruh field dibandingkan kembali dengan sumber di memori; NULL dan nol awal dipertahankan. Run ulang tidak menggandakan record.
  • Perubahan bit dan penukaran ciphertext antar-record/kolom ditolak. Tidak ada fallback plaintext.
  • Role analis ditolak membaca tabel/view per record. Koneksi protected tanpa TLS dan hostname salah ditolak.
  • Backup terenkripsi dapat di-restore; perubahan satu byte ditolak. Record sintetis yang dihapus tidak muncul pada backup baru.
  • Restore tanpa OpenBao mempertahankan ciphertext; restore dengan akses kunci diuji kembali melalui aplikasi.

Kesimpulan dan keterbatasan

Pelindungan field, pembatasan akses, keberlangsungan layanan dan restore sudah mempunyai bukti berjalan pada scope yang disebut. Hasil kinerja belum memenuhi target. Sistem ini belum menjadi bukti bahwa seluruh storage, log, aplikasi dan key plane kebal kompromi.

  • Kompromi aplikasi sekaligus kemampuan decrypt dapat membuka data sesuai kapabilitas yang dicuri.
  • Blind index mengungkap kesetaraan/frekuensi; REF dan NULL masih terlihat. Populasi sumber 734 masih memiliki proyeksi residual k=1. Suppression analis bukan differential privacy.
  • RLS berbasis setting transaksi bisa dimanipulasi pencuri credential app_user.
  • Backup lama dapat tetap berisi record yang kemudian dihapus sampai retensi berakhir.
  • DR seluruh key plane, HA, secure erase, dan audit seluruh riwayat/log host belum dibuktikan lengkap.
  • S02 historis pada salinan API memiliki kegagalan analis. Acceptance baru tidak mengganti label hasil pada lingkungan yang berbeda.
